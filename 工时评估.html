总览

阶段 名称 功能描述与阶段产出 时长/小时
1 系统加固与机房线路确认（Ubuntu 22.04 + BBR） 先验线路：三网回程与带宽体检，不合格当天换机房并重装；把 IP / dest / UUID / 证书抽成变量，再收敛基线——密钥登录、最小端口、BBR 与校时、干净快照 1.5
2 安装 Xray-core 落地核心二进制、五段式配置骨架（log / dns / inbounds / outbounds / routing）与受守护的 systemd 单元 2.5
3 配置 VLESS + REALITY 入站 无需域名与证书的 TCP 主力线路：挑伪装目标、验证书链与 ALPN、写 realitySettings 七项、Vision 流控；再模拟主动探测核对证书与页面是否与真站一致 2.5
4 配置 Hysteria2 入站（UDP） 装 hysteria 服务端与自签证书，配 443/udp 的 QUIC 入站（密码、obfs、带宽声明），nftables 把 20000-30000 端口段 DNAT 到 443 做端口跳跃，出 hy2 链接 2
5 配置 TUIC v5 入站 用 sing-box 起 TUIC 入站（4433/udp，UUID + 密码、ALPN h3、拥塞控制 bbr），复用 hy2 的证书，验语法与端口、放行 ufw 与安全组，客户端跑一次连接迁移 1.5
6 Nginx 反代与可视化面板 门面与控制台一起做：nginx 与伪装站点把 443 之外的流量装成正常小网站（面板与订阅反代走 127.0.0.1，443 留给 REALITY）；面板只监听本机、纳管三条入站、2FA 与 IP 白名单；订阅页按 UA 分流并出二维码，最后排端口归属与日志脱敏 2.5
7 分流规则与路由体系 决定「哪些流量走哪条线路」：域名/IP/端口规则集、DNS 分流、国内直连与 AI 专线 1.5
8 多用户与订阅分发 从单人自用升级为可交付：用户模型、三协议订阅链接、二维码、流量配额与吊销 1.5
9 监控告警与自动备份 可观测与可恢复：流量/连接/服务状态采集、告警通道、配置与证书定时备份 1
10 客户端部署与分流落地 四平台各一套方案：Windows（v2rayN / Clash Verge Rev）、macOS（Clash Verge Rev + 系统扩展授权 + Gatekeeper 放行）、Android（NekoBox / Hiddify + 省电白名单）、iOS（Clash Mi 主力 + Karing / Streisand 备用，全程零付费，只需一个非国区 Apple ID）；再手写 TUN + fake-ip + 同源规则集的配置，四端核对结果并整理冲突清单 2
11 TLS 指纹与主动探测对抗 上线前把特征收一遍：JA3/JA4 与真站对齐、主动探测模拟（openssl / curl / nmap）、shortId 与 spiderX 轮换、UDP 侧混淆收敛，产出暴露面自查清单 1
12 测试验收与交付 测服务、端口、出口 IP、速度、重启自启，然后交付：机器密码、机器的管理后台、可视化管理面板入口 0.5
合计 20 小时

阶段依赖与可并行点

  • 串行主干：阶段 1 → 阶段 2 必须按顺序，配置骨架没校验通过之前不要开入站。
  • 先验线路：阶段 1 的线路体检放在最前面，不合格当天就换机房；换完复测再往下走，否则后面每一步都要重做。
  • 可并行：阶段 3 / 4 / 5 三条入站彼此独立，装完核心后可以连着做，也可以分三次做；端口上只要避开 443/tcp 与 443/udp 的冲突。
  • 端口主权：阶段 6 里 nginx 与面板都只能蹲在 127.0.0.1（nginx 8443、面板另给一个本地端口），0.0.0.0:443 永远留给 REALITY；顺序反了就是 address already in use，面板自带的一键签证书要先关掉。
  • 前置依赖：阶段 6 内部顺序是「nginx 门面 → 面板 → 反代 → 纳管 → 订阅页」，反代不通就别急着往面板里加节点；阶段 7 / 8 依赖阶段 6 的面板配置读写能力；阶段 10 依赖阶段 8 的订阅链接与阶段 7 的规则定稿；阶段 11 依赖阶段 3～6 的最终配置；阶段 12 依赖全部前序。
  • 可随时插入：阶段 9 的采集与备份不阻塞主线，可以在验收前补；阶段 11 的指纹自查必须在验收前做完——验收单上要填「探测者会看到什么」的核对结论。
  • 不可并行：阶段 3 与阶段 6 在 443 上有强耦合，REALITY 的 dest 定下来之前不要动 nginx 的伪装站风格；反过来说，阶段 6 改完伪装站也不必回头改 REALITY，两者只需「同源风格」，不需要同一份文件。

阶段 1　系统加固与机房线路确认（Ubuntu 22.04 + BBR）

目标：机器一到手先确认「这条线路值不值得配」——三网回程不合格当天就换机房或换 IP，别等三个协议装完才发现晚高峰拉不动；线路确认下来之后，再把它收敛成可信基线。

产出：一份线路体检记录（去程 / 回程 / 带宽 / IP 纯净度）、必要时的机房迁移与新 IP、参数化后的配置模板与迁移清单、加固完成的 Ubuntu 22.04、ufw 规则集、/etc/sysctl.d/99-net.conf、/etc/security/limits.d/99-nofile.conf、一份干净系统快照。

流程：

  1. 拿到 IP 先做线路体检：三网去程、回程落点、带宽、IP 纯净度，晚高峰再抽测一次
  2. 不合格就在商家后台换机房或换 IP（多数商家给一次免费迁移），迁移后重装 Ubuntu 22.04 并复测
  3. 把 IP / dest / UUID / 证书路径抽成变量，后面真换机房只改变量
  4. 首次登录做基线体检（会话、爆破记录、系统版本）
  5. 全量更新并装齐网络排障工具
  6. 上传 ed25519 公钥 → 关密码登录 → 改 SSH 端口 → 双窗口验证
  7. ufw 与云安全组两层同时放行，外网侧逐个 nc -vz 验证
  8. 写内核参数（fq + bbr + fastopen + 缓冲区 + ip_forward）并核对生效值
  9. chrony 校时压到 100ms 内（REALITY 对时间敏感）
  10. 抬文件句柄上限、限日志体积
  11. 打一个干净快照作为回滚点
工作项 做什么 分钟
线路体检与机房确认 本机（家宽）跑 ping 与 mtr -rw VPS_IP 看去程；回程在 VPS 上反 trace——nexttrace / besttrace 对电信、联通、移动的测试目标各跑一次，看落点落在哪条骨干；三网视角另用在线探针（itdog.cn、ping.pe）补，无需三条宽带；带宽用 iperf3 或 curl -o /dev/null -w '%{speed_download}' 对比；再查 IP 是否在常见黑名单、是否被流媒体识别为机房 IP。晚上 20:00–23:00 再抽测一次（探针看丢包、本机看实际速率），不合格当场决定换机房 15
机房迁移与重装 商家后台迁移/换 IP（先问清换 IP 政策与是否免费），等新 IP 生效、旧 IP 释放；重装 Ubuntu 22.04，确认 uname -m 是 x86_64、记下内核版本与磁盘分区；迁移完把线路体检重跑一遍，确保不是换汤不换药 10
配置参数化与迁移清单 把 IP、dest、UUID 集、证书路径抽成变量（一份 env.sh 或模板文件），写清换机房要搬的四样：/usr/local/etc/xray、/etc/hysteria、/etc/sing-box、面板数据目录；顺手把订阅域名解析 TTL 调到 300s，否则换 IP 要干等一小时 10
首次登录 改 root 密码、who 确认没有陌生会话、lastb 看有没有人在爆破、lsb_release -a 与 uname -r 记下版本 5
更新与基础工具 apt update && apt full-upgrade -y，重启一次确认内核已更新；装 curl、wget、unzip、vim、htop、mtr、tcpdump、jq、socat、ca-certificates、net-tools 5
时区与 locale timedatectl set-timezone Asia/Shanghai、locale-gen en_US.UTF-8，避免后面日志时间与客户端对不上 5
SSH 加固 本地 ssh-keygen -t ed25519 生成密钥、ssh-copy-id 上传、/etc/ssh/sshd_config 关 PasswordAuthentication、改端口、systemctl reload ssh；先开新窗口验证能登再关旧窗口 10
防火墙 ufw default deny incoming、ufw allow 端口 逐条放行，云厂商安全组是另一层，两边都要开，放行后从外网 nc -vz IP PORT 逐个验证 5
内核调优 写 /etc/sysctl.d/99-net.conf：net.core.default_qdisc=fq、net.ipv4.tcp_congestion_control=bbr、net.ipv4.tcp_fastopen=3、rmem_max/wmem_max、net.ipv4.ip_forward=1、fs.file-max；sysctl --system 后用 sysctl net.ipv4.tcp_congestion_control 确认是 bbr 10
时间同步 apt install chrony、配就近 NTP 源、chronyc sources -v 看偏移，压到 100ms 内；误差超 60s 会让 REALITY 握手直接失败 5
连接数与日志 写 /etc/security/limits.d/99-nofile.conf（nofile 1048576，后面 systemd 单元要设 LimitNOFILE）、journalctl --vacuum-size=200M、配 logrotate 防日志撑爆小硬盘 5
快照 在商家后台打一个干净系统快照，后面配错了能一键回滚，省掉重装时间 5

本阶段小计 90 分钟。先测线路再加固，顺序反了等于白干：加固全做完才发现回程绕美西，换机房又得从 SSH 重来一遍。三条换机房红线——晚高峰 1080p 稳不住、回程三网有两条绕路、IP 已被流媒体判定为机房段。

阶段 2　安装 Xray-core

目标：把核心二进制、目录结构、五段式配置骨架和 systemd 守护装到「可以开始填入站」的状态。

产出：/usr/local/bin/xray（1.8.x 以上）、/usr/local/etc/xray/config.json（骨架，Configuration OK）、xray.service（含 LimitNOFILE 与自动重启）、预置的 geoip.dat / geosite.dat。

流程：

  1. uname -m 定架构，决定下哪个 release 包
  2. 首选官方脚本一把装完（省掉手写单元）
  3. 脚本被墙时手动装兜底（下 zip → 解二进制 → 自写单元）
  4. 规划目录与权限（配置 644、私钥 600）
  5. 手写 config.json 五大块，inbounds 故意留空
  6. 预置 geo 数据，避免首次启动联网失败
  7. xray run -test 必须输出 Configuration OK
  8. 补 systemd 单元（LimitNOFILE、Restart=on-failure）
  9. 启停一次，把 loglevel 临时调 info 看日志，稳定后回 warning
工作项 做什么 分钟
确认架构 uname -m 判断 amd64 还是 arm64，决定下哪个 release 包 8
装官方脚本 bash -c "$(curl -L https://github.com/XTLS/Xray-install/raw/main/install-release.sh)" @ install，脚本会建 /usr/local/bin/xray、/usr/local/etc/xray/、/etc/systemd/system/xray.service、/var/log/xray/ 15
手动装（备选） 脚本被墙时改手动：release 页下 Xray-linux-64.zip、unzip 解出 xray、install -m 755 xray /usr/local/bin/、自己写 systemd 单元 22
校验版本 xray version，确认 1.8.x 以上（REALITY 与 Vision 需要新版本） 5
目录规划 配置 /usr/local/etc/xray/config.json、证书 /usr/local/etc/xray/cert/、日志 /var/log/xray/；配置文件 644、私钥 600 12
写配置骨架 五大块：log（loglevel warning、access 与 error 分开）、dns（1.1.1.1 / 8.8.8.8 与 localhost 的 domains 分流）、inbounds（先留空）、outbounds（freedom + blackhole）、routing（geoip:private 与 geosite:cn 走 direct） 35
下载 geo 数据 首次启动会自动拉 geoip.dat / geosite.dat，也可手动 curl -L -o /usr/local/share/xray/geoip.dat 提前放好，避免开机联网失败 10
语法校验 xray run -test -c /usr/local/etc/xray/config.json，必须输出 Configuration OK 才继续 8
调 systemd 单元 systemctl cat xray 看官方单元、补 LimitNOFILE=1048576、Restart=on-failure、RestartSec=3 20
启停与自启 systemctl enable --now xray、systemctl status xray 确认 active、journalctl -u xray -n 50 --no-pager 看报错 10
日志观察 临时把 loglevel 调 info，tail -f /var/log/xray/error.log 边改边看，稳定后调回 warning 5

本阶段小计 150 分钟。骨架写错最常见的两处：routing 里的 domainStrategy 拼错、outbounds 少了 tag: direct 导致后面规则全不生效。

阶段 3　配置 VLESS + REALITY 入站

目标：拿下主用 TCP 线路——不需要自有域名、不需要证书，直接借真站的 TLS 指纹与证书链，被动看像在访问那个站，主动探测也拿不到区别。这是整台机器的主线，调不透后面所有测试都白测。

产出：443/tcp 上的 VLESS + REALITY + Vision 入站、一条可导入客户端的 vless:// 链接、一份「探测者会看到什么」的对照记录、一份排错清单。

流程：

  1. xray x25519 出密钥对（私钥进服务端、公钥进客户端）
  2. xray uuid 出客户端 ID，一个用户一个，方便单独停用
  3. 挑伪装目标：满足 TLS 1.3 + HTTP/2 + 非国内 + 非 Cloudflare 代理 + 不是本机——通常要试三四个候选才碰上一个合适的
  4. 用 curl -I --tlsv1.3 --http2 与 openssl s_client 验证目标可用，再看它的证书链有效期与页面是否为静态
  5. openssl rand -hex 8 出 shortId；按用户预留多个
  6. 写 inbound（vless / 443 / decryption none / flow vision / realitySettings 七项）
  7. 补 sniffing，让分流能按域名判断
  8. 校验 → 重启 → ss -tlnp 看监听，确认 443 上只有 xray 一个主人
  9. 拼客户端链接（sni / fp / pbk / sid / type），fp 要与真站浏览器族一致
  10. 浏览器直连 https://IP:443 做主动探测模拟：证书、页面、响应头三项都要与真站一致，再按清单排错
工作项 做什么 分钟
生成密钥对 xray x25519 输出 Private key 与 Public key，私钥写服务端配置、公钥留给客户端，抄错一位就连不上 5
生成 UUID xray uuid 生成客户端 ID，一个用户一个 UUID，方便日后单独停用 5
挑伪装目标 要求同时满足：TLS 1.3、HTTP/2、非国内站、非 Cloudflare 代理、非本机。候选如 www.microsoft.com、swdist.apple.com、www.lovelive-anime.jp；实际筛选通常要换三四个候选才遇到一个合适的（TLS 1.3 与 h2 都对上、又不是 CF 代理的站点比想象中少） 25
验证伪装目标 curl -I --tlsv1.3 --http2 https://目标域名 看是否 200、openssl s_client -connect 目标:443 -tls1_3 看证书链与 ALPN 是否含 h2；顺手记下证书有效期——目标站换证书那天你的 dest 也得跟着换 20
生成 shortId openssl rand -hex 8；可配多个 shortId 给不同客户端，留空字符串也允许；按用户预留，方便单独吊销 8
写 inbound protocol: vless、port: 443、listen: 0.0.0.0、decryption: none、clients 填 UUID 与 flow: xtls-rprx-vision、streamSettings.security: reality、realitySettings 填 dest（目标:443）、serverNames、privateKey、shortIds、spiderX: /；realitySettings 七项少一项都不握手 30
补 sniffing sniffing: {enabled: true, destOverride: ["http","tls","quic"]}，让路由能按域名分流 8
校验与重启 先 xray run -test，再 systemctl restart xray，ss -tlnp | grep 443；journalctl -u xray -n 30 确认没有 handshake 报错 12
生成客户端链接 手拼 vless://UUID@IP:443?encryption=none&flow=xtls-rprx-vision&security=reality&sni=目标域名&fp=chrome&pbk=公钥&sid=shortId&type=tcp#备注；fp 与真站同族，别乱填 10
主动探测模拟与排错 浏览器直连 https://IP:443，核对三项：证书链是不是真站的、页面内容是不是真站的、响应头里的 server 字段有没有露 nginx；再 openssl s_client -servername 真站域名 -connect IP:443 看 SNI 正确时是否回落真站。连不上先查三处：journalctl -u xray 的 handshake 报错、服务器时间（误差超 60s 直接失败）、客户端 pbk 与 sid 27

本阶段小计 150 分钟。伪装目标筛选是最容易被低估的一步：三四个候选里往往只有一个同时满足 TLS 1.3 + h2 + 非 Cloudflare 代理，条件卡得越死，筛掉的比例越高。取舍上——知名大站更稳但更容易被识别；小众站更隐蔽但哪天对方换证书就得跟着改。建议选一个静态资源多、常年不变的域名。写 inbound 那 30 分钟也别压：realitySettings 的 dest / serverNames / privateKey / shortIds / spiderX 五处只要错一处，表现都是「握手成功但立刻断开」，没有明确报错。

阶段 4　配置 Hysteria2 入站（UDP）

目标：补一条抗丢包、能吃满带宽的 UDP 线路（3 条线路里的第 2 条，行内俗称「腿」），用在晚高峰与跨境弱网场景，并配上端口跳跃躲开单端口 QoS。

产出：QUIC 上的 Hysteria2 服务（自签或 ACME 证书 + salamander 混淆 + 端口跳跃 DNAT）、一条 hysteria2:// 链接。

流程：

  1. 下二进制、install -m 755、验证能跑
  2. 备证书：自签（客户端开 insecure）或 acme.sh 签真证书（要域名）
  3. 写 config.yaml：listen / tls / auth / bandwidth（按实际带宽 80%）/ masquerade / obfs
  4. 自写 systemd 单元（官方没给通用模板），注意证书读权限
  5. 端口跳跃：nftables 或 iptables 把 20000-30000/UDP DNAT 到 443
  6. 持久化规则（netfilter-persistent 或 nft 规则文件）并验证重启后还在
  7. tc netem 造 30% 丢包压测，确认还能流畅播视频
  8. 出客户端链接（含 obfs 参数与端口段写法）
  9. 排错：UDP 不通的四个常见原因逐条排除
工作项 做什么 分钟
下二进制 GitHub release 下 hysteria-linux-amd64，install -m 755 到 /usr/local/bin/hysteria，hysteria version 确认能跑 10

阶段 5　配置 TUIC v5 入站（sing-box 手工）

目标：第 3 条线路，重点在移动端连接迁移——WiFi 与蜂窝网互切时不断流，这正是 TUIC 相对 Hysteria2 的核心优势。

产出：4433/udp 上的 TUIC v5 服务（复用证书、BBR 拥塞控制、关掉 0-RTT）、sing-box systemd 单元、客户端参数模板。

流程：

  1. 下 sing-box 二进制并验证版本
  2. 复用 Hysteria2 那套 cert.pem / key.pem，省一次签发
  3. 写 /etc/sing-box/config.json：type: tuic、listen_port: 4433、users、congestion_control: bbr、zero_rtt_handshake: false
  4. ss -ulnp 确认 4433 没被占、443 已是 hy2 的
  5. sing-box check + sing-box format -w 统一格式
  6. 套官方单元，启停看日志
  7. ufw allow 4433/udp + 云安全组，nc -vzu 验证
  8. 客户端填参数，WiFi/4G 来回切验证不断线
  9. 按「连上但打不开网页」「握手失败」两类症状排错

阶段 6　Nginx 反代与可视化面板（伪装站点 + 面板纳管）

目标：把这台机器做成「一个正常的小网站」，同时把三条入站从「改 JSON 重启」变成「面板里点一下」——443 上除了 REALITY 没有别的指纹可挑，面板自己不暴露任何新端口，只从反代后面进。

产出：nginx（HTTP/2 + gzip + 关版本号）与一个与 REALITY dest 同风格的静态伪装站、带 TLS 1.3 的证书与自动续期钩子、面板的反代 location（只监听 127.0.0.1）、带 2FA 与 IP 白名单的面板登录、纳管三条入站的节点列表与在线状态、订阅页与二维码、访问日志脱敏与限流规则。

流程：

  1. 装 nginx 做基础调优（连接数、keepalive、gzip、HTTP/2、隐藏版本号）
  2. 建伪装站目录与静态页，风格对齐阶段 3 借用的那个真站
  3. 签证书（acme.sh 或 Caddy 代签），443 上开 TLS 1.3 + HTTP/2，挂上续期后的 reload 钩子
  4. 选面板（3x-ui / X-UI 系）并装成只监听 127.0.0.1，装完本机 curl 确认出登录页
  5. nginx 加 location /panel/，补 WebSocket 升级头与真实 IP 头，配 allow / deny 白名单
  6. 改后台路径与端口、上强密码 + 2FA，关掉面板自带的「一键签证书」
  7. 面板里把三条入站纳管，逐条核对面板值与实际运行的配置文件一致
  8. 做订阅页：/sub/ 反代到面板的订阅接口，按 UA 返回不同格式，配二维码
  9. 排一遍「nginx 与 REALITY 共存」的坑：端口归属、stream 与 http 块的选择、SNI 分流
  10. 日志脱敏、限流、关目录列表，确认根路径回正常页面而不是默认页
工作项 做什么 分钟
安装与基础调优 apt install nginx；worker_connections、keepalive_timeout、gzip on、server_tokens off、http2 on；删掉 default 站点，避免 / 回 nginx 欢迎页 12
伪装站点 /var/www/masq 放静态页（index + 一点静态资源），风格与阶段 3 选的 serverNames 同源；nginx 只监听 127.0.0.1:8443，把 0.0.0.0:443 留给 REALITY，两个进程抢 443 是最常见的翻车点 15
证书与 HTTP/2 acme.sh --issue -d 域名 或 Caddy 代签；ssl_protocols TLSv1.3 TLSv1.2、ssl_prefer_server_ciphers on、add_header Strict-Transport-Security；续期必须挂 --reloadcmd "systemctl reload nginx"，否则 90 天后证书链自己失效 15
面板选型与安装 推荐 3x-ui 系列（自带 Xray，文档与生态快）或其他 sing-box / Xray 面板，装完只监听 127.0.0.1；本机 curl 127.0.0.1:端口 确认出登录页，此刻外网应该连不上 20
反代与 WebSocket location /panel/ { proxy_pass http://127.0.0.1:PORT/; }，带 Host / X-Real-IP / X-Forwarded-For / Upgrade / Connection 头，否则实时状态页与 WebSocket 直接断；proxy_read_timeout 调大 20
面板安全加固 改后台路径、改端口、强密码、开 2FA、会话超时；allow / deny 白名单（只放自己常在的出口 IP 与内网段）；关掉面板自带的一键签证书，它会去抢 nginx 的 80/443 15
三入站纳管核对 把 REALITY / Hysteria2 / TUIC 三条加进面板，逐字段核对面板里的值与 config.json、config.yaml、sing-box.json 一致；面板改完必须重启对应服务，改完再跑一次客户端连通性，确认「面板显示已生效」等于「客户端真连上」 18
订阅页与二维码 location /sub/ { proxy_pass http://127.0.0.1:PORT/sub/; }；面板侧按 UA 返回不同格式（clash / sing-box / v2rayN），二维码用 qrencode 或面板自带生成；订阅链接别明文走 HTTP，一定套在 443 反代下 15
端口归属与共存排错 ss -tlnp | grep -E ':443|:8443' 确认 443 只有 xray、8443 只有 nginx；想用 stream 块做 SNI 四层分流时注意它和 http 块不能抢同一个端口；curl -I https://域名 --resolve 走一遍反代链路，看 X-Forwarded-For 有没有正确传到面板 10
日志脱敏与限流 access_log 里去掉带 uuid 的查询串、limit_req_zone 给 /panel/ 上 5r/s、autoindex off，确认 404 不暴露目录结构 10

本阶段小计 150 分钟。门面和控制台本来就是一件事：nginx 是门面，面板是门后的控制台。三条红线——nginx 只准蹲 127.0.0.1:8443、0.0.0.0:443 永远归 REALITY、面板装完第一件事是关掉它自带的一键签证书。改完面板里的配置必须重启对应进程，ss -tlnp 上 443 只应该有一个主人。加出来的那一小时主要花在两处：订阅页要按 UA 分流（不同客户端吃不同格式，配错了客户端会静默导入失败），以及 nginx 与 REALITY 的端口归属要反复确认。

阶段 7　分流规则与路由体系

目标：把「3 条线路」变成「一套策略」——国内直连不绕路、国外走代理、AI 与流媒体固定走某条线路，并且规则可增量更新而不炸配置。

产出：服务端 routing 规则段 + DNS 分流策略 + 客户端同构规则、一份「什么流量走哪条线路」的对照表。

流程：

  1. 定规则源：geosite/geoip 够用就用，特殊需求再自建清单
  2. 设计 routing：按域名、IP、端口、进程四类条件落规则，顺序从具体到宽泛
  3. DNS 分流：国内域名走国内 DNS、国外走加密 DNS，防污染并控制解析延迟
  4. 规则体积治理：拆成多个 rule_set 文件，支持单独热更新
  5. 逐条验证：国内站直连、国外站代理、AI 服务走指定线路、局域网不走代理
工作项 做什么 分钟
规则源选定 优先用 geosite:cn / geoip:cn 打底；再加自建清单补漏（公司内网、常见被墙域名、流媒体分区） 15
routing 设计 rules 按「具体 → 宽泛」排：私有网段直连 → 特定域名走指定 outbound → geosite:cn 直连 → 其余走代理；每条规则带 outboundTag，避免默认落到第一条 25
DNS 分流 服务端 dns.servers 按域名分派（国内域名用 223.5.5.5、其余用 https://1.1.1.1/dns-query），hosts 兜底关键域名；注意 queryStrategy 与 IPv6 的关系 20
规则热更新与体积 把大清单拆成独立 rule_set 文件，配定时 curl 更新脚本；单文件过大启动会慢，注意 geoip.dat 的加载时机 10
分流验证 国内站看是否直连（curl -v 看出站）、国外站看是否代理、AI 服务确认走指定线路、局域网地址确认没被代理 20

本阶段小计 90 分钟。规则顺序错一位，整段策略就废：geosite:cn 的直连规则一旦排在代理规则前面，所有国内流量都会走代理。

阶段 8　多用户与订阅分发

目标：从「单人自用」升级成「可交付给别人用」——每个使用者独立凭证、独立配额、一条订阅链接搞定三协议，随时可吊销。

产出：用户清单（UUID / 密码 / 配额 / 到期）、三协议合并的订阅链接与二维码、流量统计与到期策略、增删改吊销的操作流程。

流程：

  1. 定用户模型：一条用户对应一组凭证（REALITY UUID + hy2 密码 + TUIC uuid/password），互不复用
  2. 三协议同时下发：一个订阅里给 3 条线路，客户端自动选优
  3. 生成订阅链接与二维码，注意订阅地址本身要能公网访问且不被猜
  4. 配额与到期：按流量或按时间限制，超限自动停用而不是删号
  5. 演练增删改：加一个新用户全流程走一遍，删一个看服务是否立即拒绝
工作项 做什么 分钟
用户模型 一人一组独立凭证：REALITY 一个 UUID、Hysteria2 一个密码、TUIC 一组 uuid+password；不要多协议共用一个 UUID，否则单协议吊销会牵连其他 15
三协议同时下发 一个订阅地址返回三条节点：vless://、hysteria2://、tuic://，客户端按延迟或手动排序 20
订阅链接与二维码 订阅地址走面板或自建静态服务，路径加随机串；生成二维码方便手机扫；确认订阅内容不会被搜索引擎/目录扫描收录 20
流量统计与到期策略 按用户统计流量（面板自带或 xray stats API），配额到 90% 提醒、到 100% 停用；到期时间提前三天提醒 20
增删改与吊销演练 加一个新用户 → 客户端导入 → 能连；删掉该用户 → 服务重启 → 同链接必须连不上；改密码验证旧密码立即失效 15

本阶段小计 90 分钟。订阅地址本身就是凭证：谁能访问谁就能拿到全部节点，别放进任何公开仓库或聊天记录。

阶段 9　监控告警与自动备份

目标：节点挂了、流量超了、磁盘满了，能在用户报障之前知道；配置和证书能在误操作之后 5 分钟内恢复。

产出：服务状态与流量采集、一条可用的告警通道（Telegram Bot 或邮件 webhook）、每天自动备份配置与证书的脚本 + 恢复步骤。

流程：

  1. 采集：服务是否 active、端口是否在听、当日流量、连接数、磁盘水位
  2. 告警：写最小脚本 + cron，异常时推到 Telegram Bot 或邮件
  3. 备份：配置、证书、面板数据打包，本地留 7 天 + 异地一份
  4. 日志与磁盘治理：轮转、压缩、清理阈值
工作项 做什么 分钟
指标采集 systemctl is-active 三服务 + ss 端口检查 + vnstat 日流量 + df -h 水位，写成一个 health.sh，输出带时间戳的一行摘要 20
告警通道 Telegram Bot sendMessage 或邮件 webhook；只在状态变化时推（避免刷屏），cron 每 5 分钟跑一次 health.sh 15
配置与证书备份 tar 打包 /usr/local/etc/xray、/etc/hysteria、/etc/sing-box、面板数据目录；本地 /root/backup 留 7 天滚动，异地走对象存储或另一台机器 15
日志与磁盘治理 写 /etc/logrotate.d/ 规则（按天、保留 7 份、压缩），journalctl --vacuum-size，磁盘到 80% 也进告警 10

本阶段小计 60 分钟。小硬盘机型最容易被日志与 geoip.dat 更新撑爆，先把水位告警接上再谈备份。

阶段 10　客户端部署与分流落地（Windows / macOS / Android / iOS）

目标：四个平台各有一套「装完就能用」的客户端方案，且调出来的分流结果与服务端同构——不是「Windows 上能用」，是「四端跑得一样」。iOS 端走零付费路线，不买 Shadowrocket。

产出：Windows / macOS / Android / iOS 四套客户端与配置、一份手写的客户端配置（TUN + fake-ip + 同源规则集）、四端一致的核对记录、一份「换设备怎么恢复」的三行说明、一份 iOS 免费客户端与三条线路的兼容性对照。

流程：

  1. Windows：v2rayN（轻、原生 Xray）与 Clash Verge Rev（规则强）各装一个，比出主力
  2. macOS：装 Clash Verge Rev（与 Windows 同一份 Clash YAML，直接复用），过 Gatekeeper 首次放行与 Network Extension 系统扩展授权
  3. Android：NekoBox / Hiddify，开 VPN 模式、加省电白名单、配分应用代理
  4. iOS：先备一个非国区（美区）Apple ID（免费注册、无需付款方式），App Store 切区后装 Clash Mi 作主力，再用 Karing / Streisand 验单链接；不买 Shadowrocket
  5. iOS 按线路配参数：REALITY 要 client-fingerprint: chrome 与 reality-opts；hy2 / tuic 都要 udp: true、自签证书开 skip-cert-verify；iOS 默认走 hy2 出口
  6. 手写一份客户端配置：TUN 模式、DNS 用 fake-ip、规则集指向与服务端同源的地址
  7. 四端各导一次，用同一批站点核对出口 IP 与是否直连
  8. 结果不一致时按顺序查：客户端自带 GeoIP → 系统代理与 TUN 同时开 → DNS 被劫持
  9. 写一份换设备的恢复说明，连同订阅二维码一起交付
工作项 做什么 分钟
Windows v2rayN 与 Clash Verge Rev 各装一个：v2rayN 直接吃 vless:// 与 hysteria2://，Clash Verge Rev 规则能力强但要转换订阅；开 TUN 模式、设开机自启，确认系统代理与 TUN 不同时开 18
macOS 装 Clash Verge Rev（macOS 版，与 Windows 端同一份 Clash YAML 直接复用，不用另写配置）：首次打开要过 Gatekeeper（右键打开或 xattr -d com.apple.quarantine）；装 Network Extension 系统扩展并在「系统设置 → 隐私与安全性」授权，未授权时 TUN 起不来、只走系统代理；scutil --proxy 确认系统代理状态，TUN 模式下把「设为系统代理」关掉。备选 v2rayN 无 macOS 版，要单链接就用 V2Box 或 NekoRay 16
Android NekoBox 或 Hiddify，导入订阅、开 VPN 模式；把 App 加进省电白名单（MIUI / HyperOS 还要关「后台弹出界面」限制）否则锁屏后被杀；配分应用代理，让国内 App 不走代理 16
iOS 选型与安装 注册一个非国区（美区）Apple ID（免费、无需付款方式），App Store 切区后装 Clash Mi（免费、mihomo 内核，与 Windows 端 Clash Verge Rev 同源，一份 Clash YAML 两端通用）作主力；再装 Karing 与 Streisand 作备用（都免费，前者双内核带新手模式、能直接吃 vless:// / hy2:// 单链接，后者最轻量、协议覆盖全）。不买 Shadowrocket / Stash；V2Box、Happ 虽免费但不支持 TUIC，sing-box MT 只吃 JSON 配置，留给自用 14
iOS 三线路参数与兼容验证 Clash Mi 里三条线路逐条配通：REALITY 写 client-fingerprint: chrome、reality-opts.public-key、reality-opts.short-id、servername 填伪装目标的 SNI；hy2 与 tuic 都要 udp: true、自签证书开 skip-cert-verify: true、tuic 补 alpn: [h3]。三个坑：① 只给它 Clash YAML，别丢单链接（它的订阅转换弱）；② 必须开 TUN + dns.enhanced-mode: fake-ip，否则规则「看着生效实际全直连」；③ 装完先去「设置 → 通用 → VPN 与设备管理」确认 Network Extension 已授权，连不上先看这里而不是怀疑节点。iOS 默认出口走 hy2，避开 sing-box 系对 flow: xtls-rprx-vision 的兼容差异 14
客户端配置手写 tun: {enable: true, stack: system}、dns: {enhanced-mode: fake-ip}、rule-providers 指向与服务端同源的 rule_set 地址；关掉客户端自带的一键分流，避免两套规则打架 14
四端一致性核对 同一批站点（国内 3 个、国外 3 个、AI 1 个）在四端各查一次出口 IP 与是否直连；把「哪端走了代理、哪端直连」的差异列成表，差异处就是配置不一致的地方。iOS 端额外验一次「单链接能不能通」，那是阶段 3、4 的产出物 15
冲突排查清单 三条按顺序查：客户端自带 GeoIP 覆盖了自定义规则、系统代理与 TUN 同时开、DNS 被运营商劫持；每条附验证命令（curl ifconfig.me、scutil --proxy、dig @223.5.5.5） 9
恢复说明与二维码 写三行「换设备怎么恢复」：装哪个客户端、扫哪个二维码、开哪两项开关；二维码与订阅链接一起存进手机备忘录与密码库，别只留在一台机器上。iOS 那行注明「非国区 Apple ID 才能装」 4

本阶段小计 120 分钟。四端真正吃时间的是平台差异而不是配置本身：macOS 卡在系统扩展授权、Android 卡在厂商的省电策略、iOS 卡在「非国区 ID 装客户端」与三条线路的参数对齐，Windows 反而最省事。iOS 端全部选免费客户端（Clash Mi 主力 + Karing / Streisand 备用），零付费，代价是要多花十分钟注册美区 Apple ID 并切区；Clash Mi 与 Windows 端同为 mihomo 内核，一份 Clash YAML 两端通用，所以它不只是「免费替代」，而是让四端一致性最容易达成的那条路。客户端不需要「功能全开」，需要「四端结果一致」；不一致时先怀疑客户端的本地规则，再怀疑服务端。

阶段 11　TLS 指纹与主动探测对抗

目标：把「像不像那个真站」从配置层面做到指纹层面。REALITY 已经借了证书链，但 JA3/JA4、HTTP/2 的 SETTINGS、QUIC 的初始包长这些细节对不上，一样能被筛出来。

产出：一条与真站对齐的指纹链、一次主动探测模拟的记录、多 shortId 的分配表、一份「哪些行为会暴露这台机器」的自查清单。

流程：

  1. 查真站的指纹：JA3/JA4、HTTP/2 SETTINGS、支持的扩展顺序，作为对齐目标
  2. 客户端 fingerprint 选与真站同一浏览器族，别用 randomized 每次都变
  3. 自己模拟探测：不带客户端、只做 TLS 握手和 HTTP 请求，看会不会露馅
  4. shortId 按用户分配、定期轮换；spiderX 指向真站真实路径
  5. UDP 侧收敛特征：混淆密码强度、masquerade 回落、ALPN 与 QUIC 版本
  6. 把可能暴露的行为逐条过一遍，形成清单
工作项 做什么 分钟
真站指纹采集 用 tls.peet.ws / browserleaks.com/tls 访问 dest 域名，记下 JA3、JA4、HTTP/2 SETTINGS（INITIAL_WINDOW_SIZE、MAX_FRAME_SIZE）、扩展顺序与 ALPN；这就是要对齐的靶子 15
客户端指纹对齐 客户端 fingerprint 填 chrome / firefox / safari 中与真站同族的一个；randomized 每次握手都变，反而比固定更像工具；对完再用同一工具复测 JA3 是否一致 15
主动探测模拟 openssl s_client -connect IP:443 -servername dest域名 -tls1_3 看证书链是否回落真站；curl -I --tlsv1.3 --http2 https://dest域名 --resolve dest域名:443:IP 看响应头是否同源；nmap --script ssl-enum-ciphers -p 443 IP 看套件顺序；浏览器直连 https://IP:443 看是否露出默认页 15
shortId 与 spiderX 一个用户一个 shortId，便于单独停用；spiderX 填真站的真实子路径（如 / 或某个静态目录），探测者抓到的抓取路径与真站一致；轮换 shortId 不必改端口 8
UDP 侧特征收敛 hy2 的 obfs: salamander 密码要长且随机；masquerade 指向真站而不是 nginx 默认页；TUIC 的 alpn: h3 与 QUIC 版本要和主流客户端一致；关掉不必要的 0-RTT 暴露面 7

本阶段小计 60 分钟。指纹这件事只有「一致」和「不一致」两种结果，没有中间态：真站是 Chrome 的 JA3，客户端却用 Firefox 的指纹，握手特征一对就露。清单里最容易被忽略的两条——面板路径可猜、订阅 URL 明文走 HTTP，这两个比 TLS 指纹更容易暴露。

阶段 12　测试验收与交付

目标：把机器从头到尾真跑一遍——服务在跑、端口通、出口 IP 变了、速度不掉、重启能自己回来，然后把密码、后台、面板入口交到用的人手上。

产出：一份打勾的验收单、3 条线路的横评记录（哪条最快、哪条晚高峰最稳），以及一份交付说明（root 密码或密钥、SSH 端口、面板地址与账号、订阅链接）。

流程：

  1. 服务与端口：三个服务都 active，443/tcp、443/udp、4433/udp 都在听
  2. 出口 IP 与分流：连上后出口变成 VPS 的 IP，国内直连、国外代理、AI 走指定线路
  3. 速度：与裸连对比测一次，晚高峰再补一次
  4. 3 条线路横评：REALITY / Hysteria2 / TUIC 各跑一轮
  5. 重启自启：reboot 之后服务自己回来，客户端不改配置照样能连
  6. 交付：机器密码与 SSH 端口、机器的管理后台、可视化管理面板的入口与账号，一次性交给使用的人
工作项 做什么 分钟
服务与端口 systemctl status xray hysteria-server sing-box --no-pager 三个都 active；ss -tlnp 看 443/tcp、ss -ulnp 看 443/udp 与 4433/udp 5
出口 IP 与分流 客户端连上后访问 https://ip.sb 确认变成 VPS 的 IP（不能省的一步）；国内站直连、国外站代理、AI 服务走指定线路 5
速度 fast.com 与 speedtest 各测一次，记录与裸连的差距；至少测一个晚高峰时段 5
3 条线路横评 REALITY、Hysteria2、TUIC 各测一轮，记下哪条最快、哪条晚高峰最稳、哪条在弱网最抗 5
重启自启 手机 WiFi 与 4G 互切；服务器 reboot 后确认三个服务都自启、客户端不改配置就能连 5
交付 写一份交付说明：root 密码或 SSH 密钥与 SSH 端口、机器的管理后台（商家控制台，能重启、重装、打快照）、可视化管理面板（https://域名/panel/ 的账号与 2FA，能看三个节点、改配置）、订阅链接、三份文档位置。交付前用手机流量登一次面板，确认不是只在本机能用 5

本阶段小计 30 分钟。reboot 这一项一定要做：手工 systemctl start 起来的服务，重启机器后不会自己回来。交付不是甩个 IP 就完事——机器密码、管理后台、可视化面板三样都得能让人自己登进去，看见三个节点在跑。
