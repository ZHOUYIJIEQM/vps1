为什么流量要打对折：这几家里除 DMIT 和 Vultr 外都是「双向计费」——你看 1 GB 视频，数据先从源站进 VPS（入站 1 GB），VPS 再出给你（出站 1 GB），一共记 2 GB。所以标称流量 ÷ 2 才是真实能用的量。DMIT 和 Vultr 是例外，只算单向，标多少就是能用多少

自建节点

优点

  • ip 比较干净，用国外 AI 不容易被封号
  • 流量比较多
  • 有一台远程服务器可以用

缺点

  • 现阶段机器普遍涨价，性价比不高
  • 单个 ip 如果被防火墙封锁，节点就失效，得等自行解封，或者加钱找服务商更换 ip
  • 科学上网方案没有百分之百能避免封锁的方案。听说现在还有用 AI 去检测流量特征，很多机器被识别到

不过一般不去发布政治言论、流量不算太夸张，一般不会被封。我之前的那个节点稳定运行了 1 年半，但这次国家 10 月 26 号开五中全会，vps 的所有 tcp 连接都被封了，只有用 TUIC 还能勉强使用；开完会差不多一个星期，tcp 封锁就解除了。

最终组合建议（四层保险）：

主力：VLESS + REALITY (TCP 443)        ← 日常全走这个，抗封锁最强
备用：Hysteria2 (UDP 443 + 端口跳跃)    ← 晚高峰/移动网络切这个，暴力抢带宽
备用：TUIC v5 (UDP 4433)               ← hy2 被 QoS 或频繁切网时换它
兜底：VLESS + WS + TLS + CF CDN        ← IP 被墙时启用

TUIC 为什么值得加：它和 Hysteria2 同属 QUIC 系，但侧重不同。hy2 的强项是暴力拥塞控制（BBR 硬抢带宽，丢包 30% 还能跑满）；TUIC 的强项是多路复用 + 连接迁移（0-RTT 重连，手机从 WiFi 切 4G 不断线）。 实际用法：家里宽带稳定、只是晚高峰挤 → 用 hy2；手机 4G/5G 移动中使用、经常切换网络 → 用 TUIC 体验更好。 两个都开，成本为零（同一个 UDP 端口范围，不同端口号），客户端哪个快用哪个。

搭建方案结论

  • 主力协议：VLESS + REALITY（TCP 443，Vision 流控） —— 不需要域名、不需要证书、抗 SNI 阻断最强
  • 备用协议：Hysteria2（UDP 443 + 端口跳跃） —— 晚高峰丢包环境下速度碾压 TCP 系
  • 第三条腿：TUIC v5（UDP 443 或独立端口） —— 同样是 QUIC 系，但多路复用和连接迁移比 hy2 强，hy2 被 QoS 时换它
  • 兜底方案：VLESS + WS + TLS + Cloudflare CDN —— IP 被墙了还能救回来
  • 面板：使用 S-UI（sing-box） 搭建，TUIC 只有 sing-box 系（S-UI / 纯 sing-box）能开

S-UI 详细搭建教程

S-UI 是基于 sing-box 的 Web 面板（GitHub: alireza0/s-ui），协议支持比 3X-UI 更广。

安装（Debian 12 / Ubuntu 22.04+）

# 1. 基础环境
apt update && apt install -y curl sudo

# 2. 一键安装（中文安装器）
SUI_LANG=zhcn bash <(curl -Ls https://raw.githubusercontent.com/alireza0/s-ui/master/install.sh)

# 3. 查看状态
systemctl status s-ui
systemctl status sing-box

安装脚本会自动装好 s-ui 主程序 + sing-box 内核，并注册两个 systemd 服务。

Docker 方式（可选）：

mkdir s-ui && cd s-ui
docker run -itd \
  -p 2095:2095 -p 2096:2096 -p 443:443 -p 80:80 \
  -v $PWD/db/:/app/db/ \
  -v $PWD/cert/:/root/cert/ \
  --name s-ui --restart=unless-stopped \
  alireza7/s-ui:latest

首次登录与安全加固（必做）

  1. 浏览器打开 http://IP:2095/app/，用 admin/admin 登录
  2. 立刻在「设置 → 管理员」改用户名 + 强密码（16 位以上）
  3. 「设置 → 面板」改面板端口（比如 38471）和路径（比如 /mysecret/）
  4. 云厂商安全组/防火墙只放行：SSH 端口、新面板端口、443、80
  5. 强烈建议配域名 + HTTPS（见「配 HTTPS 面板」一节）

添加 Hysteria2 入站（备用，抗丢包）

先自签证书（不需要域名）：

mkdir -p /root/cert && cd /root/cert
openssl req -x509 -nodes -newkey ec:<(openssl ecparam -name prime256v1) \
  -keyout key.pem -out cert.pem -subj "/CN=www.bing.com" -days 36500

「入站列表 → 添加」：

字段 值
协议 Hysteria2
端口 443（UDP）
证书路径 /root/cert/cert.pem
私钥路径 /root/cert/key.pem
密码 自定义强密码
混淆(Obfs) salamander + 密码（可选，抗 QoS 有效）

客户端配置需开 insecure: true（自签证书）或 skip-cert-verify: true。

端口跳跃（强烈建议，防 UDP QoS）：

# 把 20000-30000 的 UDP 流量全部重定向到 443
iptables -t nat -N HY2
iptables -t nat -A HY2 -p udp -m multiport --dport 20000:30000 -j REDIRECT --to-ports 443
iptables -t nat -A PREROUTING -p udp -j HY2

# 持久化
apt install -y iptables-persistent && netfilter-persistent save

客户端服务器地址填：你的IP:20000-30000

添加 TUIC v5 入站（第二条 UDP 腿）

TUIC 是只有 sing-box 系才支持的协议——3X-UI（Xray 内核）开不了，纯 Xray 也开不了。所以： - 用 S-UI → 面板里直接有 TUIC 入站，填表即可 - 用 3X-UI → 想要 TUIC 就得在机器上另外跑一个 sing-box 进程（见「3X-UI 用户想加 TUIC」一节）

心跳 10s 默认即可
0-RTT 握手 关闭 ⚠️ sing-box 官方明确警告：0-RTT 有重放攻击风险（Attack of the clones），必须关
TLS 证书 /root/cert/cert.pem
TLS 私钥 /root/cert/key.pem

3X-UI 用户想加 TUIC（旁挂 sing-box）

3X-UI 只管 Xray，TUIC 靠 sing-box 单独跑，两者端口不冲突可以共存：

# 1. 装 sing-box（官方脚本）
bash <(curl -fsSL https://sing-box.app/install.sh)

# 2. 写服务端配置
mkdir -p /etc/sing-box
cat > /etc/sing-box/config.json <<'EOF'
{
  "log": { "level": "warn", "timestamp": true },
  "inbounds": [
    {
      "type": "tuic",
      "tag": "tuic-in",
      "listen": "::",
      "listen_port": 4433,
      "users": [
        {
          "name": "me",
          "uuid": "把这里换成你自己生成的UUID",
          "password": "把这里换成强密码"
        }
      ],
      "congestion_control": "bbr",
      "auth_timeout": "3s",
      "zero_rtt_handshake": false,
      "heartbeat": "10s",
      "tls": {
        "enabled": true,
        "server_name": "www.bing.com",
        "certificate_path": "/root/cert/cert.pem",
        "key_path": "/root/cert/key.pem"
      }
    }
  ],
  "outbounds": [
    { "type": "direct", "tag": "direct" }
  ]
}
EOF

# 3. 校验配置（必须过，不过别启动）
sing-box check -c /etc/sing-box/config.json

# 4. 启动并开机自启
systemctl enable --now sing-box
systemctl status sing-box --no-pager

UUID 生成：cat /proc/sys/kernel/random/uuid 或面板里点生成。 端口 4433 记得在防火墙放行 UDP：ufw allow 4433/udp。

客户端配置（sing-box / mihomo / Shadowrocket 通用）

{
  "type": "tuic",
  "tag": "tuic-node",
  "server": "你的VPS_IP",
  "server_port": 4433,
  "uuid": "你的UUID",
  "password": "你的密码",
  "congestion_control": "bbr",
  "udp_relay_mode": "native",
  "zero_rtt_handshake": false,
  "heartbeat": "10s",
  "tls": {
    "enabled": true,
    "server_name": "www.bing.com",
    "insecure": true
  }
}

关键字段解释：

字段 值 为什么
udp_relay_mode native 原生 UDP 转发，游戏/语音最流畅。备选 quic（封装进 QUIC 流，穿透性更好但多一层开销）
congestion_control bbr 服务端客户端都要设 bbr，否则退回 cubic 速度差一半
zero_rtt_handshake false 安全，防重放攻击
insecure true 因为用自签证书；有域名配了正式证书就改 false

TUIC vs Hysteria2 到底选哪个

维度 Hysteria2 TUIC v5
拥塞控制 自定义 BBR，暴力抢带宽最强 标准 QUIC BBR，稍保守
丢包环境（30% 丢包） ★★★★★ 仍能跑满 ★★★★ 明显下降
多路复用 弱（每个请求一条流） 强（QUIC stream 复用）
连接迁移 ❌ 切网要重连 ✅ 切 WiFi/4G 不断线
0-RTT 支持 支持（但建议关，防重放）
协议成熟度 高（作者专职维护） 中（2025 年重启维护，原作者说明）
服务端支持 sing-box / 官方 hy2 仅 sing-box 系（Xray 不支持）
抗 QoS 中（可加 salamander 混淆） 中（无官方混淆，靠端口跳跃）

结论： - 只开一个 → 选 Hysteria2（生态更成熟、丢包环境更强、有混淆） - 两个都开（推荐，零额外成本）→ hy2 走 443/udp，TUIC 走 4433/udp，手机用 TUIC、家里用 hy2 - 必须用 3X-UI → TUIC 只能旁挂 sing-box，多一层维护成本，不如直接上 S-UI

3X-UI 搭建教程（REALITY 主力方案）

# 安装
bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)

# 装完会随机生成用户名/密码/访问路径，运行 x-ui 查看
x-ui

x-ui 菜单里可以：启停服务、查看/重置登录信息、设置面板端口、申请 SSL 证书、管理 xray 配置。

添加 REALITY 入站： 1. 面板 → 「入站列表」→「添加入站」 2. 协议 vless，端口 443，传输 tcp (raw) 3. 安全 reality 4. dest 填 www.microsoft.com:443，serverNames 填 www.microsoft.com 5. 点「Get New Cert」旁的钥匙图标生成私钥/公钥，shortIds 填随机 16 位 hex 6. Flow 选 xtls-rprx-vision 7. 保存 → 点「二维码」或复制 vless:// 链接

非交互安装（cloud-init / 批量部署）：

纯命令行 Xray + REALITY（无面板，最稳）

# 1. 安装 Xray
bash -c "$(curl -L https://github.com/XTLS/Xray-install/raw/main/install-release.sh)" @ install

# 2. 生成 UUID 和密钥对
xray uuid
xray x25519     # 输出 Private key / Public key

# 3. 写配置
cat > /usr/local/etc/xray/config.json <<'EOF'
{
  "log": { "loglevel": "warning" },
  "inbounds": [{
    "listen": "0.0.0.0",
    "port": 443,
    "protocol": "vless",
    "settings": {
      "clients": [
        { "id": "在此填UUID", "flow": "xtls-rprx-vision" }
      ],
      "decryption": "none"
    },
    "streamSettings": {
      "network": "tcp",
      "security": "reality",
      "realitySettings": {
        "show": false,
        "dest": "www.microsoft.com:443",
        "xver": 0,
        "serverNames": ["www.microsoft.com"],
        "privateKey": "在此填私钥",
        "shortIds": ["0123456789abcdef"]
      }
    },
    "sniffing": { "enabled": true, "destOverride": ["http", "tls", "quic"] }
  }],
  "outbounds": [
    { "protocol": "freedom", "tag": "direct" },
    { "protocol": "blackhole", "tag": "block" }
  ],
  "routing": {
    "rules": [
      { "type": "field", "protocol": ["bittorrent"], "outboundTag": "block" }
    ]
  }
}
EOF

# 4. 启动
systemctl restart xray
systemctl enable xray
systemctl status xray

vless://UUID@你的IP:443?encryption=none&flow=xtls-rprx-vision&security=reality&sni=www.microsoft.com&fp=chrome&pbk=公钥&sid=0123456789abcdef&type=tcp#节点名

系统层必做优化

开 BBR（速度提升关键）

cat >> /etc/sysctl.conf <<'EOF'
net.core.default_qdisc=fq
net.ipv4.tcp_congestion_control=bbr
net.ipv4.tcp_fastopen=3
net.core.rmem_max=16777216
net.core.wmem_max=16777216
EOF
sysctl -p
lsmod | grep bbr        # 确认 bbr 已加载

时间同步（REALITY 对时间敏感，误差 >60s 直接失败）

apt install -y chrony
systemctl enable chrony --now
chronyc tracking

SSH 加固

# 1. 本地生成密钥，上传公钥
# 2. 编辑 /etc/ssh/sshd_config
PasswordAuthentication no
PermitRootLogin prohibit-password
Port 22222            # 改成非 22

systemctl restart ssh

防火墙

apt install -y ufw
ufw default deny incoming
ufw default allow outgoing
ufw allow 22222/tcp     # SSH
ufw allow 443/tcp
ufw allow 443/udp
ufw allow 面板端口/tcp
ufw enable

云厂商（阿里云/腾讯云/AWS）还要在控制台安全组里放行，两层都要开。
